# Daniels 跑步 AI 助手设计稿

## 1. 目标

做一个长期可用的私人跑步助手，核心训练逻辑严格以 Jack Daniels 的训练体系为准，并结合 COROS MCP 读取的训练历史、恢复指标和用户手动输入的跨运动信息，持续给出可执行的训练建议、跑后复盘，以及周 / 月 / 周期总结。

这个助手不是“自动生成计划”的工具，而是一个会根据现实生活动态改课表的教练型系统。它要能处理这些常见情况：

- 第一次使用时，需要先读取近期训练数据并结合目标成绩初始化训练状态。
- 每日建议必须根据历史数据和当天现实条件动态调整。
- 跑步以外的活动，例如篮球、力量训练、拉伸、通勤疲劳，也必须纳入训练负荷判断。
- 每次跑后都必须输出分析。
- 长期使用时，不能依赖聊天上下文记忆，要有独立的记忆架构。

## 2. 设计原则

1. 训练理论优先于生成能力。AI 负责解释、调整、总结，不负责自由发挥训练逻辑。
2. 训练刺激必须可解释。每一条建议都要说明它对应 Daniels 体系中的哪种训练目的。
3. 现实优先。熬夜、加班、篮球、力量训练、出差、疼痛、临时空档变化，都可以触发训练降级、改期或替换。
4. 记忆必须结构化。长期信息不能只存在对话上下文里。
5. 默认保守。宁可少给一次强度，也不要把恢复不够的人硬推去做质量课。

## 3. 系统边界

### 输入

- COROS MCP 的训练历史数据
- COROS 恢复相关指标
- 用户手动输入的非手表活动记录
- 用户目标成绩、比赛日期、赛季目标
- 用户临时状态：睡眠、加班、疲劳、疼痛、可用时长

### 输出

- 今日训练建议
- 跑后复盘
- 周总结
- 月总结
- 周期总结
- 训练状态变化提醒

### 非目标

- 不做医疗诊断
- 不替代医生、物理治疗师或正式教练
- 不在第一版里自动写入 COROS 训练日历
- 不把 Daniels 体系简化成“泛耐力模板”

## 4. 训练理论底座

本产品采用 Daniels 训练体系作为唯一主理论框架。实现时只保留可解释的规则，不把训练逻辑混成其他流派的默认建议。

### 4.1 核心概念

- **VDOT**：作为当前能力的近似指标，用于推导训练配速和训练强度。
- **E**：轻松跑，主要服务于有氧基础、恢复、跑量积累。
- **M**：马拉松配速，服务于专项耐力与配速经济性。
- **T**：阈值跑，服务于乳酸阈值提升和持续输出能力。
- **I**：间歇跑，服务于最大摄氧量相关刺激。
- **R**：重复跑，服务于速度、跑姿、神经肌肉效率。

### 4.2 规则摘要

- 训练课必须先知道目的，再生成配速和结构。
- 训练强度要和当前 VDOT 匹配，而不是和主观目标成绩直接硬对齐。
- 大部分训练应落在低强度与恢复友好的区域。
- 质量课要服务于周期目标，不能连续堆叠。
- 如果恢复状态不佳，强度课要降级为 E 跑、缩短时长，或改为休息。
- 跑量和强度的提升应保守进行，避免连续多周激进上升。

### 4.3 训练规则实现要求

- 训练规则必须配置化，不写死在对话提示里。
- 规则引擎的输出要包含“训练目的、建议类型、建议时长、建议配速或心率区间、降级理由”。
- 对外展示时，要让用户看得懂“为什么今天这样练”。

## 5. 关键数据模型

### 5.1 长期档案

固定或低频更新的信息：

- 基本信息：年龄段、性别可选、身高体重可选
- 跑步历史：训练年限、常见配速区间、受伤史
- 目标偏好：5K / 10K / 半马 / 全马 / 健康跑
- 训练偏好：可训练日、可训练时长、是否接受双练
- 禁忌与限制：膝、跟腱、足底、腰背等问题

### 5.2 动态状态

每日变化的信息：

- 近 7 / 28 / 90 天跑量
- 强度分布
- 近期关键训练完成度
- COROS 恢复与训练负荷指标
- 睡眠、疲劳、静息心率、HRV 等可用指标
- 近期篮球、力量训练、其他运动负荷

### 5.3 事件记录

每一次活动都记为事件，类型包括：

- 跑步训练
- 比赛
- 测试跑
- 力量训练
- 篮球
- 拉伸 / 康复
- 熬夜 / 加班 / 出差 / 生病 / 疼痛

每个事件至少保存：

- 时间
- 类型
- 时长
- 主观强度
- 对下次跑步的影响
- 备注

## 6. 记忆架构

长期记忆不依赖聊天上下文，而采用三层结构。

### 6.1 长期档案层

保存相对稳定的信息，供初始化和全局偏好调用。

### 6.2 状态摘要层

定期从事件记录压缩出的当前状态，重点包含：

- 当前 VDOT 估计
- 最近训练趋势
- 恢复状态
- 近期非跑步负荷
- 当前周期重点

### 6.3 事件明细层

保存原始训练和生活事件，用于回溯和复盘。

### 6.4 摘要刷新规则

- 每次跑后更新一次局部摘要
- 每周生成一次周摘要
- 每月生成一次月摘要
- 每个训练周期结束生成周期摘要

这样做的目的，是保证即使上下文丢失，也能从“档案 + 最新摘要 + 原始事件”恢复系统状态。

## 7. 首次初始化流程

首次使用时，系统要先完成初始化，而不是直接给训练计划。

### 7.1 读取内容

- 近期 COROS 跑步历史
- 近期恢复指标
- 最近一次比赛或测试成绩
- 目标比赛与目标成绩
- 近期篮球、力量等非跑步活动

### 7.2 初始化输出

- 当前 VDOT 估计
- 当前训练阶段判断
- 风险级别
- 第一版训练建议
- 需要用户确认的事项

### 7.3 初始化原则

- 如果数据不足，默认保守估值
- 如果近期有篮球或重力量训练，跑步状态要按更谨慎的恢复水平处理
- 如果没有可靠比赛成绩，必须标明 VDOT 为估算值

## 8. 每日建议流程

每日建议是系统最常用的功能。

### 8.1 决策输入

- 昨天和近几天的跑步历史
- 今日睡眠、疲劳、可用时长
- 今天是否加班、出差、熬夜
- 是否有篮球或力量训练安排
- 当前周期目标

### 8.2 决策逻辑

1. 先判断今天是否适合做质量课。
2. 如果恢复不足，优先选择 E 跑、缩短训练、或休息。
3. 如果今天时间不够，优先保留 Daniels 体系里最核心的刺激，删掉次要部分。
4. 如果今天还有篮球或腿部力量训练，跑步课必须重新排序。
5. 如果连续几天都被现实打断，要重新评估本周结构，而不是机械补课。

### 8.3 输出格式

- 训练类型
- 训练目的
- 建议时长
- 建议配速 / 区间
- 替代方案
- 降级理由

## 9. 跑后复盘流程

每次跑完都必须自动复盘。

### 9.1 复盘目标

- 判断是否完成了 Daniels 目标刺激
- 判断配速是否过快或过慢
- 判断恢复成本是否过高
- 判断下次训练是否要改

### 9.2 复盘内容

- 这次训练属于 E / M / T / I / R 中哪一类
- 是否符合目标配速或训练意图
- 心率、配速、节奏、体感是否一致
- 是否出现明显漂移、掉速、早疲劳
- 是否受到篮球、力量、睡眠不足等外部因素影响
- 下一次建议如何调整

### 9.3 复盘原则

- 复盘要明确，不要只说“表现不错”
- 复盘要结合上下文，不只看单次记录
- 复盘要给出下一步动作

## 10. 周 / 月 / 周期总结

### 10.1 周总结

回答的问题：

- 本周训练是否符合周期目标
- 跑量和强度分布是否合理
- 非跑步活动是否影响恢复
- 下周是否需要减量或强化

### 10.2 月总结

回答的问题：

- VDOT 和状态趋势如何变化
- 训练一致性是否稳定
- 疲劳是否在累积
- 哪类训练最常被打断
- 哪些现实因素最常影响训练

### 10.3 周期总结

回答的问题：

- 这个训练块是否完成预期适应
- Daniels 目标刺激是否达成
- 是否应该进入下一周期
- 是否要调整目标比赛或节奏

## 11. 非跑步活动处理

篮球和力量训练不会出现在 COROS 数据里，但仍然必须纳入决策。

### 11.1 手动输入

用户通过 OpenClaw 手动记录非跑步活动。

### 11.2 影响建模

- 篮球：高冲击、高变向、高神经负荷，通常对次日跑步恢复影响较大
- 力量训练：尤其下肢重训，会影响后续质量课和长跑
- 拉伸 / 康复：通常可视为恢复性活动

### 11.3 决策后果

- 次日高强度课可降级
- 长距离可缩短
- 连续负荷时可插入恢复日

## 12. OpenClaw 与 COROS MCP 分工

### 12.1 COROS MCP

负责读取训练历史、恢复指标和相关训练数据。当前能力以只读分析为主。

### 12.2 OpenClaw

负责主动交互和任务编排：

- 早上给出今日建议
- 跑后自动发起复盘
- 接收篮球 / 力量等手动日志
- 生成周报、月报、周期总结
- 保存结构化记忆

### 12.3 分工原则

- COROS 是数据源
- OpenClaw 是执行层和对话层
- 训练规则引擎是中间层

## 13. 风险与边界

- 不能把任何疼痛解释成训练正常波动
- 不能把恢复不足的人硬推进质量课
- 不能让 VDOT 乐观估值长期失真
- 不能把篮球和力量训练忽略掉
- 不能依赖聊天上下文当作唯一记忆
- 不能把 Daniels 体系和其他训练流派混成一锅

## 14. 验收标准

1. 首次使用能完成初始化，并给出当前训练状态和建议。
2. 每天能根据 COROS 数据和手动活动记录动态给出建议。
3. 每次跑步后都能输出结构化复盘。
4. 能生成周 / 月 / 周期总结。
5. 能记住用户长期目标、偏好、受伤史和训练习惯。
6. 在篮球、力量训练、熬夜、加班等干扰下，建议仍然合理。
7. 所有建议都能解释为 Daniels 体系内的训练决策。
